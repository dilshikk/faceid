# Безопасность

BCC получает доступ к чувствительным сведениям о сервере и логам, поэтому
безопасность реализуется до того, как панель открывается во внешний мир.

## 8.1. Принципы

- Отдельный Linux-пользователь `bcc` без root-привилегий.
- Минимальные права на чтение только разрешённых журналов и статусов.
- Не использовать общий `sudo systemctl *` и произвольное выполнение
  команд — только фиксированные read-only вызовы
  (`systemctl show <unit> --property=...`, `journalctl -u <unit> -n N`).
- Backend слушает `127.0.0.1`; внешний доступ — только через Nginx и
  HTTPS.
- Хеширование паролей Argon2id, ограничение попыток входа, отзыв сессий.
  Двухфакторная аутентификация для администраторов — предусмотреть на
  следующем этапе (не входит в код MVP).
- Белый список Telegram ID; серверная проверка полномочий для каждой
  команды (реализовано в `backend/app/telegram_admin/handlers.py`).
- Секреты хранятся вне репозитория (`/etc/bot-control-center/bcc.env`),
  права доступа не шире необходимых.
- Маскирование токенов и паролей в логах (`app/core/security.py:
  mask_secret`); секреты запрещены в `config_json` и `audit metadata`.
- Защита от CSRF при cookie-сессиях (`SameSite=Lax`, `Secure`,
  `HttpOnly`), от XSS (React escaping по умолчанию), SQL injection
  (SQLAlchemy параметризованные запросы), SSRF (unit-имена проверяются
  строгим паттерном) и перебора паролей (рекомендуется добавить
  rate-limiting на уровне Nginx).
- Аудит входов, изменения настроек и всех привилегированных действий —
  таблица `audit_logs`.

## 8.2. Роли

| Роль | Разрешения |
|---|---|
| owner | Полные настройки BCC, управление пользователями и мониторинг |
| admin | Просмотр служб, логов, инцидентов и настройки уведомлений |
| viewer | Только чтение разрешённых статусов, метрик и логов |

Для MVP можно начать с `owner` и `viewer`. Любые функции управления
службами (старт/стоп/restart) должны проектироваться отдельно и требовать
явного подтверждения и аудита — в текущем коде такие операции **не**
реализованы намеренно (TZ, раздел 1, "вне рамок MVP").

## Чеклист перед открытием панели во внешний мир

- [ ] `SECRET_KEY` и `DATABASE_URL` в `/etc/bot-control-center/bcc.env`
      заданы случайными значениями, файл доступен только пользователю
      `bcc`.
- [ ] HTTPS включён, HTTP редиректит на HTTPS (см. `deploy/nginx/bcc.conf`).
- [ ] Хотя бы один пользователь с ролью `owner` создан вручную (вставкой в
      таблицу `users` с хешем пароля из `passlib`).
- [ ] `TELEGRAM_ADMIN_IDS` содержит только проверенные Telegram ID.
- [ ] Юниты BCC запускаются от пользователя `bcc`, не root.
- [ ] Firewall разрешает входящие только на 80/443 для веб-панели.
